## MCP Server Architecture

The MCP server is an HTTP endpoint exposed by the Laravel application. Agents running inside Docker containers call it to interact with Kodizm's data.

```
Docker Container (Agent)
  │
  │  HTTP requests to KODIZM_MCP_ENDPOINT
  │  Authorization: Bearer {KODIZM_MCP_TOKEN}
  ↓
Laravel MCP Server
  │
  │  JWT middleware: verify → extract claims → scope queries
  ↓
Database (PostgreSQL)
  │
  ├── tasks, task_sections
  ├── projects
  └── project_documents
```

- **Endpoint**: Configurable port (default 4096), served by the Laravel application
- **Auth**: Signed JWT token (`KODIZM_MCP_TOKEN` env var in container)
- **Scoping**: All queries scoped to the project from JWT claims — agents cannot access data outside their assigned project
- **Role-based access**: Some tools restricted to specific agent roles (BA, Lead Dev)

## Key Design Decisions

- **HTTP transport** — MCP uses HTTP/JSON, not stdio. Container sends requests to the Laravel server.
- **JWT self-contained** — No DB lookup needed for token validation (JWT contains all claims). DB field is backup.
- **Project-scoped** — Every MCP tool operation is scoped to the project from JWT claims. No cross-project access.
- **Embedding is POST-MVP** — The `embedding` field exists but is nullable. Semantic search via pgvector is post-MVP; MVP uses keyword/LIKE search.
